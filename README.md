# MARKZ — маркировка и рядовка заполнений витража

**Редакция:** `Ред. 48.30` (см. `*mark:rev*` в [MARKZ.lsp](MARKZ.lsp))  
**Файл:** [`MARKZ.lsp`](MARKZ.lsp) → копировать как `D:\MARKZ.lsp` (кодировка ANSI/CP1251)  
**Репозиторий (справочно):** https://github.com/moleval/MarkZ  

Один модуль AutoLISP: раскладка заполнений по ячейкам, марки, рядовка обозначений, ведомость.

---

## Установка

```lisp
(load "D:/MARKZ.lsp")
```

В консоли должно появиться `[MARKZ] Загружен Ред. 48.30` и список команд.

## Обновление модуля (каждый раз после правок)

В папке с локальной копией репозитория (например, `D:\MarkZ`):

```text
git fetch origin
git pull --ff-only origin arena/01a0e6a0-markz
```

затем в AutoCAD перезагрузить модуль:

```lisp
(load "D:/MarkZ/MARKZ.lsp")
```

В консоли должно появиться `[MARKZ] Загружен Ред. 48.30` — если редакция старая,
обновление не применилось.

## Команды

| Команда | Алиас | Что делает |
|---------|-------|------------|
| **МАРКАЗАП** | `MARKA` | Полный цикл: Источник [Сетка/Заполнения] → вставка (Сетка) → марки → рядовка → ведомость; **один UNDO** |
| **МАРКАРОВКАЗАП** | `MARKZ` | Марки блоков «Заполнение в витраж»: TEST 00–16, расчёт секций/ярусов, запись атрибута «Марка» после PRE-CHECK |
| **МАРКАЗАПРЯД** | `MARKAR` | Рядовка из блоков «Ряд заполнений»: номера снизу, буквы справа |
| **МАРКАЗАПТАБЛ** | `MARKTABLE` | Ведомость: таблица AutoCAD + XLS (CSV — фолбэк), файл «Шкала.txt» |
| **МАРКАЗАПБЛОК** | `MARKFILL` | Вставка «Заполнение в витраж» по ячейкам; **марки не пишет** |
| `Сетка-мультилинии`, `Точка-мультилинии`, `Сетка-динамика`, `Точка-динамика`, `Полилинии` | — | Прямой запуск режимов 1/2/3/4/7 МАРКАЗАПБЛОК |
| **МАРКАЗАПТЕСТ** | — | Проверка ячейки на тестовом блоке из линий |
| **МАРКАЗАПГЕО** | — | Включить [DIAG]-печать геометрии секций на следующий МАРКАЗАП |
| **МАРКАЗАПКОПИИ** | — | Собрать полные дубли объектов в группу и подсветить (без удаления) |
| **МАРКАДИАГ** | — | Диагностика: что за блок стоит у окна/двери и как его видит LISP |

### МАРКАЗАП — полный цикл

```text
МАРКАЗАП → Источник [Сетка/Заполнения] <Сетка>
```

- **Сетка (Enter):** Этап 1/4 МАРКАЗАПБЛОК (режим 5-Сетка: каркас рамкой) → раскладка
  заполнений по ячейкам → Этап 2/4 МАРКАРОВКАЗАП (свежевставленные блоки — без
  перевыделения) → Этап 3/4 МАРКАЗАПРЯД → Этап 4/4 МАРКАЗАПТАБЛ.
- **Заполнения (`З`):** Этап 1/3 МАРКАРОВКАЗАП (выбор готовых блоков + каркас рамкой
  для расчёта секций) → Этап 2/3 МАРКАЗАПРЯД → Этап 3/3 МАРКАЗАПТАБЛ.
- Весь пакет — одна транзакция UNDO.

### МАРКАЗАПБЛОК — режимы

| Режим | Ключ | Примитивы |
|-------|------|-----------|
| 1-Сетка-мультилинии | `1` (умолчание) | мультилинии рамкой |
| 2-Точка-мультилинии | `2`, `Т` | точка внутри ячейки из мультилиний |
| 3-Сетка-динамика | `3` | динамические блоки рамкой |
| 4-Точка-динамика | `4`, `Д` | точка внутри ячейки из блоков |
| 5-Сетка-все-типы | `5` | **динамика + мультилинии** (движок МАРКАЗАП «Сетка») |
| 6-Точка-все-типы | `6` | точка: полилиния-контур, динамика, мультилинии |
| 7-Полилиния | `7`, `P` | указание замкнутых полилиний-контуров ячеек |

## Каркас: с какими примитивами работаем (Ред. 48.6)

**Правило (решение от 2026-09-29):** в автоматическом режиме МАРКАЗАП каркас —
**только мультилинии (MLINE) и динамические блоки**. Отрезки (LINE) и дуги (ARC) —
не каркас. Полилиния-контур ячейки — только режимы точки (2/6) и 7-Полилиния.

| Куда попадает выбор | Каркас (учитывается) | Не каркас (пропуск со счётчиком в логе) |
|---|---|---|
| МАРКАЗАП «Сетка» (режим 5) | динблоки, MLINE | LINE, ARC, полилинии (замкнутые и незамкнутые), скрытые слои, блоки проёмов |
| МАРКАЗАП «Заполнения» (каркас секций) | динблоки, MLINE | то же |
| МАРКАЗАПБЛОК 1/2 | MLINE | — |
| МАРКАЗАПБЛОК 3/4 | динблоки | — |
| МАРКАЗАПБЛОК 5 | динблоки + MLINE | LINE, ARC, полилинии |
| МАРКАЗАПБЛОК 6 | точечный поиск (полилиния-контур разрешена) | — |
| МАРКАЗАПБЛОК 7 | замкнутые полилинии | — |

Полуширина (отступ контура ячейки от оси): линии динблоков — **0** (точная геометрия),
MLINE — из её фактического габарита. До Ред. 48.6 отрезок принимался как каркас
с допущением полуширины 25 мм — теперь отрезки в сеточных режимах пропускаются:
«[INFO] Отрезков и дуг пропущено: N — не каркас (только мультилинии и динамика)».

Шкала секций (источник «Р», зеркало MarkZV) строится **только** по MLINE и
блокам-ригелям («\*ригель\*») — случайные примитивы на неё не влияют.

## Формула марки

```text
марка = [Витраж " "] + БУКВА[.литера] + НОМЕР[.подындекс] + [стм/снд]
```

- **БУКВА** — ярус (высота ячейки); шкала ярусов строится из высот всех замкнутых
  ячеек каркаса, включая проёмные и глухие (Ред. 48.8 — буквы не сдвигаются, если
  в проёме позже появится заполнение новой высоты); литера после точки — подъярус
  по высоте: `Б.а12`.
- **НОМЕР** — секция (ширина в свету, зеркально шкале MarkZV); подындекс — подъячейка
  по ширине: `Б12.1`. Оба разделителя — точка.
- **Префикс** — атрибут «Витраж» из блока «Атрибуты витража» (TEST 02/03): `В-7 Г1снд`.
- Суффиксы спецсостояний Visibility — строчными: `стм`, `снд`.

Примеры: `А1`, `Б12.1`, `Б.а12.1стм`, `В-7 Г1снд`. Алфавит — 29 букв, без Ё, Й, З, О.
Одинаковый размер (допуск 0,5 мм) → один базис «буква+литера+номер+подындекс».

## Рядовка (кратко)

- Обозначения — **из марок** (номер/буква с подындексами); пустая марка — запасной
  индекс от размера (WARN в логе).
- Сортировка натуральная: `9 < 10 < 12.1 < 13`; `А < А.а < Б`.
- Ряд 0 сплошной; наложения — линиями ниже/правее с шагом **150 мм**, по убыванию длины.
- Dynamic-размер блока ряда: **L/2 + 25** мм. Горизонталь — поворот 270°, вертикаль — 0°.
- Группы: `Рядовка горизонтальная`, `Рядовка вертикальная`.

## Ведомость (кратко)

- Заголовок **«Заполнение»**; колонки `№ | Тип | Марка | Высота, мм | Ширина, мм | Кол-во, шт. | Площадь, м2`.
- Припуск размеров: **+26 мм**; таблица — на слое **«Размеры»**.
- XLS с формулами; CSV — тихий фолбэк. Рядом пишется **«<имя чертежа> Шкала.txt»**:
  `индекс;размер_мм;источник` — ключ к номерам секций и сверка с MarkZV.

## Самодиагностика

При МАРКАРОВКАЗАП: **TEST 00–16** + **[DIAG]** по базисам.

| TEST | Содержание |
|------|------------|
| 00 | Баланс скобок исходника (при загрузке) |
| 01 | Блоки «Заполнение в витраж» |
| 02/03 | «Атрибуты витража» и атрибут «Витраж» (префикс марок) |
| 04–06 | DP «Ширина/Высота в свету» и их значения |
| 07 | Visibility State |
| 08 | Атрибут «Марка» |
| 09–11 | Шкалы размеров, буквы, нумерация секций |
| 12 | Спецсостояния (Стемалит/Сэндвич) |
| 13 | Формирование марок в памяти; размеры печатаются в целых мм (Ред. 48.7); «без гео» — предупреждение (Ред. 48.5) |
| 14 | PRE-CHECK (запись только после OK) |
| 16 | Секции и ярусы: источники `Р`/`З`/`РЗ`, подъячейки по возрастанию (Ред. 48.7), конфликты базисов |

`[DIAG]` — группировка по (W,H)±0,5 мм: одинаковый размер → один базис. При «?»
в базисе (буква яруса или номер секции не определены) — подсказка с причиной
и отсылкой к TEST 13 (Ред. 48.9); на чертежах без «?» вывод не меняется.

## Синхронная работа с MarkZV (кратко)

Подробно — [SYNC_MARKZV.md](SYNC_MARKZV.md). Методика:

1. **Каркас чертится мультилиниями и динамическими блоками** — их видят обе программы
   (правило Ред. 48.6).
2. **MarkZV (МАРКАВ)** маркирует стойки/ригели: `РгN` по длинам ригелей
   (Блок 1 — уникальные длины по возрастанию).
3. **MarkZ (МАРКАЗАП)** маркирует заполнения: номер секции = номеру ригеля той же
   длины (зеркальные правила расчёта длин), буква — ярус, подындексы `.1`/`.а`.
4. **Контроль:** TEST 16 — на исправном чертеже все секции `РЗ` (ширина секции =
   длине ригеля); файл «Шкала.txt» — машинная сверка шкал обеих программ.
5. **Расхождение** → TEST 16 локализует секцию; правило правится в одной функции
   сбора длин, остальная логика не затрагивается.

Роли: MarkZV — профили (стойки/ригели, «т»); MarkZ — заполнения, рядовка, ведомость,
Шкала.txt.

## История редакций (основное)

- **48.30:** при нескольких витражах в выделении — вопрос режима:
  `[Совместная/Раздельная] <Совместная>` (ключи Совместная/Раздельная/
  С/Р/Enter). **Совместная** (ожидание заказчика): элементы ВСЕХ витражей
  вычисляются вместе — шкалы секций и строк ОБЩИЕ на всё выделение
  (как в логе 48.28-мульти: 14 секций, 20 строк), марки = префикс
  витража + индексы общих шкал (карта ename-префикс
  `*mark:vz-map*` строится из кластеров, `mark:vz-rec-pfx` в
  `mark:build-marks`); TEST 02 при нескольких блоках печатает INFO
  о совместной маркировке (WARN остаётся для standalone без карты),
  TEST 03 дополнительно «Значения: ТБ-1, В-7», ИТОГ «Витражи: …».
  **Раздельная**: каждому витражу свои шкалы (механизм 48.29 без
  изменений). Рядовки в обоих режимах per витраж (свои базы Y/X и
  группы), индексы — из марок. Карта и режим сбрасываются при новом
  выборе (`mark:select`). Ведомость: сортировка **тип, витраж,
  маркировка** (`mtab:mark-split` делит марку по последнему пробелу,
  сравнение `mark:nat-less`; порядок строк таблицы меняется во всех
  прогонах — требование заказчика). При одном витраже вопрос не
  задаётся, путь и лог прежние. Фикс после контрольного прогона:
  зависание ведомости на сортировке — в `mark:nat-key<` не было
  инкремента `i`, при равных первых токенах вечный цикл (в старой
  сортировке ветка nat-less была фактически мёртвой — вызывалась
  только на идентичных записях, которых после агрегации нет);
  добавлены инкремент и эквивалентность равных ключей ('eq).
- **48.29:** несколько витражей в одном прогоне МАРКАЗАП. Решения
  заказчика: порог разрыва между витражами **2500 мм**
  (`*mark:vz-gap*`); ведомость и Шкала.txt — **одна на всех**; при
  двух и более блоках «Атрибуты витража» в одном кластере — WARN,
  берётся ближайший к центру; витраж без блока — марки без префикса
  (TEST 02 NOT FOUND), прогон продолжается. Механизм: заполнения
  кластеризуются по связности bbox (зазор меньше порога по обеим
  осям — один витраж; проёмные ячейки не разрывают); каждый блок
  «Атрибуты витража» привязывается к ближайшему кластеру; затем
  `mark:vz-marks` / `mark:vz-rows` (замена прямых вызовов в
  `mark:a-all`, оба режима) ведут per витраж: свой префикс, свои
  шкалы секций/строк (fill-geo фильтруется по кластеру), свои
  марки, свои рядовки — горизонтальная снизу СВОЕГО габарита,
  вертикальная справа СВОЕГО, группы «Рядовка … <префикс>».
  Витражи нумеруются слева направо («--- Витраж 1 из N: ТБ-1 —
  заполнений 25 ---»). Дефект первой сборки 48.29 устранён:
  очередь кластеризации хранит записи (ename bbox), а bbox
  извлекался повторным assoc ПО записи (не по ename) → nil →
  «; ошибка: неверный тип аргумента: consp nil» на ЛЮБОМ прогоне
  с этапом 2, включая одиночный витраж; исправлено — bbox берётся
  (cdr e0) прямо из записи очереди. Ведомость общая: в логе перечень
  «[INFO] Витражи: ТБ-1, В-7» (mtab:prefix), позиции различаются
  префиксами марок. ВАЖНО: при одном кластере поведение и лог
  побайтово прежние (обёртка вызывает mark:main / mark:ar-main
  напрямую). Standalone-команды МАРКАРОВКАЗАП/МАРКАЗАПРЯД не
  менялись (один витраж на прогон). Шкала.txt — сводный по секциям
  всех витражей (fill-geo общий), строки «-;» — из последнего
  рассчитанного витража.
- **48.28:** группировка старых рядовок сохраняется. Дефект
  (2026-09-30): прогон первого МАРКАЗАП группирует рядовку; прогон
  второго витража — тоже, но РАЗГРУППИРОВЫВАЕТ рядовку первого.
  Причина: имена групп были фиксированные («Рядовка горизонтальная/
  вертикальная»), а `mark:ar-make-group` перед созданием удалял
  одноимённую группу (`vla-Delete`) — расформировывая чужую рядовку.
  Фикс: (1) имя группы теперь с суффиксом витража — «Рядовка
  горизонтальная В-7» (без префикса — базовое имя; `mark:ar-prefix`
  — тихий расчёт, в МАРКАЗАП уже вычислен МАРКАРОВКАЗАП); (2)
  существующая группа не удаляется и не пересоздаётся — новые
  вставки добавляются в неё (`AppendItems`): повторный прогон того
  же витража ДОПОЛНЯЕТ его группу, старые члены остаются; (3)
  legacy-группы без суффикса (созданы до 48.28) не трогаются вовсе.
  Лог: при создании «Группа "…": N объект(ов)», при добавлении
  «Группа "…": добавлено N, всего M объект(ов)».
  ВНИМАНИЕ: в первичном прогоне строки групп меняются — «Рядовка
  горизонтальная В-7» вместо «Рядовка горизонтальная» (ожидаемое
  отличие 48.28); остальные строки лога и все расчёты — без
  изменений. Прогоны подтверждены (два витража подряд в одной
  сессии): В-7 и ТБ-1 — эталоны 100%, группы обоих витражей живы
  после второго прогона («<Группа вкл>» — клик выделяет группу);
  единственное отличие логов от эталонов — суффикс в имени групп.
- **48.27:** вопросы ведомости МАРКАЗАПТАБЛ понимают русские ключи.
