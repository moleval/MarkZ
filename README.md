# MARKZ — маркировка и рядовка заполнений витража

**Редакция:** `Ред. 48.2` (см. `*mark:rev*` в [MARKZ.lsp](MARKZ.lsp))  
**Файл:** [`MARKZ.lsp`](MARKZ.lsp) → копировать как `D:\MARKZ.lsp` (кодировка ANSI/CP1251)  
**Репозиторий (справочно):** https://github.com/moleval/MarkZ  

Один модуль AutoLISP: марки заполнений, рядовка обозначений, ведомость.

---

## Установка

```lisp
(load "D:/MARKZ.lsp")
```

В консоли должно появиться `[MARKZ] Загружен Ред. 48.2` и список команд
(МАРКАЗАП, МАРКАЗАПБЛОК, МАРКАЗАПРЯД, МАРКАЗАПТАБЛ, МАРКАРОВКАЗАП и др.).

В папке с локальной копией репозитория (например, `D:\MarkZ`):

В консоли должно появиться `[MARKZ] Загружен Ред. 48.2` — если редакция старая,
обновление не применилось.

## Команды

| Команда | Что делает |
|---------|------------|
| **МАРКАЗ** (`MARKZ`) | Пишет атрибут «Марка» в «Заполнение в витраж» |
| **МАРКАР** (`MARKAR`) | Рядовка: блоки «Ряд заполнений» (буквы снизу, номера справа) |
| **МАРКАТАБЛ** (`MARKTABLE`) | Ведомость: AutoCAD-таблица, XLS, CSV (фолбэк) |
| **МАРКА** (`MARKA`) | Один выбор → все три этапа, **один UNDO** |
| **МАРКАЗАЛ** (`MARKFILL`) | Блоки «Заполнение в витраж» по ячейкам; атрибуты пустые |

### МАРКАЗАЛ / MARKFILL

```text
МАРКАЗАЛ → Режим [Сетка/Точка/Полилиния] <Сетка> → выбор объектов
```

| Режим | По умолчанию / Ключи | Как работает |
|-------|----------------------|--------------|
| **Сетка** | **Enter**, `С`, `S`, `1` | Выбор элементов витража (MLINE, LINE, ARC) → автоматическое определение границ, фильтрация открытых проёмов, объединение Т-образных стыков стоек/ригелей и расчёт всех ячеек |
| **Точка** | `Т`, `T`, `2` | Указание точки внутри замкнутого контура ячейки (поиск границ в окне 5000 мм) |
| **Полилиния** | `П`, `P`, `3` | Указание готовых замкнутых полилиний границ ячеек |

- **Особенности геометрии и вставки:**
  - Вставка в **левый нижний** угол ячейки (rot 0).
  - Свойства `Ширина в свету` и `Высота в свету` равны точным габаритам светового проёма ячейки.
  - Поддержка **MLINE** (мультилиний) со стойками/ригелями: центральные оси вычисляются через AABB, узлы округляются до 1 мм.
  - **Т-образные примыкания (T-junctions):** если промежуточная стойка подходит снизу к ригелю и не продолжается вверх, ячейки над ригелем автоматически объединяются в единый сквозной проём (например, фрамуга).
  - **Контроль наклона стоек:** строгий допуск `*mark:fill-slope* = 0.0033` (не более 10 мм на 3000 мм высоты) исключает ложные срабатывания.
  - **Очистка атрибутов:** атрибуты нового блока гарантированно обнуляются после установки размеров (чтобы исключить дефолтные значения динамического блока).
  - **Замкнутость ячеек сетки (Ред. 47.5):** стойки на обеих осях ячейки должны перекрывать её по высоте, ригели сверху/снизу — по ширине; ячейка шире `*mark:fill-max-w*` (3000 мм) или выше `*mark:fill-max-h*` (4500 мм) считается разрывом между участками — заполнение к незамкнутому участку не «прилипает», пропущенные ячейки считаются и печатаются в лог.
  - **Фактическая полуширина MLINE (Ред. 47.5):** полуширина стойки/ригеля берётся из габарита самой мультилинии (`mark:fill-mline-hw`), а не жёсткие 25 мм — стойка 40 или 50 мм даёт верный световой размер.
  - **Блоки проёмов — не каркас (Ред. 47.6):** окна/двери (маски `*mark:opening-masks*`: ОКНО/СТВОР/ДВЕР) исключаются из каркаса во **всех** режимах (Сетка-динамика, Точка-динамика, блок под точкой): линии рамы заходят в световой проём (нахлёст) и занижали ячейку (например, −5 мм с каждой стороны). Каркас — только стойки, ригели и направляющие; в динамических режимах пропущенные проёмы считаются и печатаются в лог.
  - **Лог проёмов (Ред. 47.6):** полный список «[INFO] Проём: …» печатается только в режимах сетки (где задана зона `*mark:grid-zone*`); в «Точка/Полилиния» — только счётчик «Проёмов для фильтра: N».
  - **5-Сетка-все-типы и 6-Точка-все-типы (Ред. 47.7):** рамкой/точкой принимаются блоки, мультилинии, линии, полилинии и дуги одновременно. Чисто линейный выбор считается конвейером 1-Сетка-мультилинии (оси, Т-объединение, замкнутость), чисто блочный — конвейером 3-Сетка-динамика, смешанный каркас — единым расчётом осей (`mark:fill-seg-items` + `mark:fill-items->cells`): ячейка может быть собрана, например, из блоков-стоек и мультилиний-ригелей. Убран O(n²) дедуктор отрезков.
  - **МАРКАЗАП — Этап 1 = 5-Сетка-все-типы (Ред. 47.7):** источник «Сетка» пакета теперь принимает все типы объектов сразу (раньше — только MLINE/LINE/ARC); полный цикл одной командой доступен и для блочного каркаса.
  - **Маркировка с членением через Т-соединение (Ред. 48.0):** секции и ярусы по правилу опор: секция — интервал в свету между соседними колонками, на которые опираются торцами ригели (импосты не границы — они создают подъячейки); ярус — между ригелями, охватывающими секцию. Марка = БУКВА [. литера подъяруса] НОМЕР [. подындекс ширины] суффикс: `Б12`, `Б12.1`, `Б.а12`, `Б.а12.1стм`. Шкала номеров «в свету» зеркалит MarkZV Ред. 3.7 (Блок 1 — длины ригелей, Блок 2 — секции без ригеля): цифра секции = цифре ригеля той же длины. Подындексы глобальны по номеру/букве: одинаковые изделия — одинаковые марки.
  - **TEST 16 (Ред. 48.0):** таблицы секций и ярусов с источниками РЗ/З и подъячейками; контроль соответствия шкалы MarkZV. Шкала пишется в «<имя чертежа> Шкала.txt» (индекс;размер_мм;источник).
  - **Скрытые слои — не каркас (Ред. 48.0):** объекты на выключенных или замороженных слоях пропускаются в 5-Сетка-все-типы (счётчик в логе) — скрытая полилиния больше не становится ячейкой.
  - **Готовые заполнения — с каркасом (Ред. 48.0):** МАРКАРОВКАЗАП без раскладки просит выделить каркас рамкой и считает секции на месте (сопоставление по точке вставки).
  - **Исправление формирования марок (Ред. 48.1–48.2):** записи с секцией/ярусом терялись в первом проходе `build-marks` (`rec-put` возвращает новый список, `foreach` его не сохранял), а аккумулятор записей не сбрасывался между проходами — список удваивался, и вперёд вставали старые записи без марки. Теперь записи сохраняются и сбрасываются между проходами; TEST 13 при сбое печатает причину (нет гео секции / нет буквы яруса / нет номера шкалы); гео секций/ярусов округляется до целых мм (уходит шум вида `259.99999938`).
  - **Рядовка и ведомость (Ред. 48.0):** обозначения берутся из марок (`12`, `12.1`, `12.2` / `Б`, `Б.а`, `Б.б`), натуральная сортировка `9 < 10 < 12.1 < 13`; геометрия расстановки рядовки не менялась. Таблица ведомости — на слое «Размеры». Пропуски «неполный контур» печатаются с координатами. Спецсуффиксы — строчными: `стм`/`снд`.
  - **Полилинии — контуры ячеек, отступа нет (Ред. 47.8):** в режимах 5/6 замкнутая полилиния — это готовая ячейка: берётся её габарит без отступа (семантика 7-Полилиния); раньше её отрезки попадали в оси с полушириной 25 мм и уменьшали ячейку на 50 мм с каждой стороны. В 5-Сетка-все-типы контур крупнее `*mark:fill-max-w*`/`*mark:fill-max-h*` — не ячейка, а контур участка (пропуск со счётчиком). Незамкнутая полилиния и старый POLYLINE — рамка из линий с полушириной 0. В 6-Точка-все-типы точка внутри замкнутой полилинии даёт её контур напрямую (как в 2/7).
  - **Лог TEST 13 (Ред. 47.8):** одна строка на блок — «Блок N: W x H / Видимость > Марка» — с выравниванием колонок по ширине (`mark:rjust`), без пустых строк между блоками.

### Универсальный запуск — команда МАРКА

Команда **МАРКА** объединяет весь сквозной цикл проектирования:
```text
МАРКА → Режим [Сетка/Заполнения] <Сетка>
```
1. **Режим `Сетка` (по умолчанию / Enter):**
   - **Этап 1: МАРКАЗАЛ** — выбор каркаса (блоки, мультилинии, линии, полилинии, дуги — режим 5-Сетка-все-типы), раскладка блоков заполнений в ячейки.
   - **Этап 2: МАРКАЗ** — автоматический подхват созданных блоков, выбор «Атрибутов витража», расчёт и запись марок (`А1`, `Б2`...).
   - **Этап 3: МАРКАР** — построение рядовки условных обозначений.
   - **Этап 4: МАРКАТАБЛ** — формирование ведомости заполнений (AutoCAD / Excel / CSV).
   - Весь процесс выполняется в **единой транзакции UNDO** (откат одной командой `_U`).
2. **Режим `Заполнения` (`З`, `F`):**
   - Выполняет этапы 2-4 по уже существующим на чертеже блокам заполнений.

## Формула марки

```text
[Витраж] + БУКВА(по ширине) + НОМЕР(по высоте) + суффикс
```

Примеры: `А1`, `Б3стм`, `В2снд`

| Visibility | Суффикс |
|------------|---------|
| Стемалит | `стм` |
| Сэндвич | `снд` |

Алфавит без **Й** и **З**. Одинаковый размер (допуск 0.5 мм) → один базис «буква+номер».

## Рядовка (кратко)

- Индекс `Ряд` = **от размера W/H** (та же логика, что МАРКАЗ), не от строки марки.
- Основной ряд — сплошной; наложения — на линиях ниже/правее с шагом **150 мм**, по убыванию длины.
- Dynamic-размер блока: **L/2 + 25** мм.
- Горизонталь — поворот **270°**, вертикаль — **0°**.
- Группы: `Рядовка горизонтальная`, `Рядовка вертикальная`.

---

## Ведомость (кратко)

- Заголовок **«Заполнение»**
- `№ | Тип | Марка | Высота, мм | Ширина, мм | Кол-во, шт. | Площадь, м2`
- Припуск размеров в таблице: **+26 мм**
- XLS с формулами; CSV только если XLS не создался (в меню CSV нет)

---

## Самодиагностика

При каждой МАРКАЗ: **TEST 00–14** + **[DIAG]** по базисам stem/сэнд.

- `TEST 00` — баланс скобок исходника (падает сразу при повреждении файла).
- `TEST 14` — PRE-CHECK; запись только после OK.
- `[DIAG] КОНФЛИКТОВ: N` — у заполнений одного типоразмера разные базисы (сверить W/H в свойствах).

## Конфигурация (важные переменные)

| Переменная | Значение по умолчанию |
|------------|------------------------|
| `*mark:block-fill*` | `Заполнение в витраж` |
| `*mark:attr-mark*` | `Марка` |
| `*mark:prop-width*` / `height` | `Ширина в свету` / `Высота в свету` |
| `*mark:ar-block*` / `ar-attr*` | `Ряд заполнений` / `Ряд` |
| `*mark:ar-offset*` | 1000 |
| `*mark:ar-line*` | 150 |
| `*mtab:allowance*` | 26 |
| `*mark:specials*` | Стемалит→`стм`, Сэндвич→`снд` |

Имена блоков/DP должны **точно** совпадать с чертежом.
